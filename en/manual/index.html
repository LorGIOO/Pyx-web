    Welcome

    Pyx is an editor for LaTeX documents with Python cells inside. In the same file you write the text of the report, do the calculations and place their results in the text; when you compile, Pyx runs the cells, puts each value in its place and produces the PDF. If you change a datum, everything that depends on it updates by itself: the number in the paragraph, the table, the plot and the conclusion.

    It is meant for people who write technical documents with numbers in them (calculation reports, lab reports, academic work, project annexes) and are tired of copying results from a spreadsheet or from Jupyter into the document, only to find out later that the PDF and the calculations no longer agree.

    1.1 What Pyx does#

    A complete LaTeX editor.
    Highlighting, completion of more than 300 commands and environments, error checking as you type, spelling and grammar, folding, bookmarks and project-wide search: what you expect from TeXstudio.
    Python cells, as in Jupyter.
    Blocks of code inside the document, with their output below: text, tables, plots, formulas. Real completion with jedi and help for every function.
    Your notebooks and scripts, without repeating the calculation.
    A Jupyter notebook (.ipynb) or a .py file is linked to the document and its variables are used just like those of a cell. If the notebook is open in VS Code or Jupyter, Pyx takes its values from there instantly, without running anything.
    A bridge from calculation to text.
    \py{expression} writes the value of a Python expression in the PDF, and \pyif chooses one text or another depending on the result.
    Data from Excel, without Python.
    \hoja links a workbook and \celda places a cell or a whole range.
    A built-in PDF viewer.
    The PDF sits next to the code, with jumps in both directions (Ctrl+click), search, bookmarks and annotations.
    Speed.
    Pyx recomputes only the cells a change affects and keeps LaTeX with the preamble already loaded, so the PDF updates in tenths of a second while you type.

    1.2 What is new in version 2.2#

    • Excel and CSV data without Python: \hoja links a workbook and its sheet, and \celda places a cell or a whole range, ready for a table (chapter 9).
    • Open folder: the project folder stays in the explorer of the side panel, which looks like VS Code's (section 3.2).
    • A PDF night mode that only darkens the paper and lightens the text: colours, plots and pictures are kept (chapter 12).
    • Ctrl+T on a word or phrase comments only the selection, and bold or italics with the caret in a \py{} apply to the whole command.
    • LaTeX's working files no longer stay on the computer: they are deleted when Pyx closes (section 4.5).
    • Completion and the problems panel look like VS Code's, a new document starts empty and the settings are also saved in a readable file.

    1.3 What is new in version 2.0#

    • Faster compiles: Compile & view uses the LaTeX engine with the preamble already loaded and writes the PDF with light compression. In a real 18-page report each pass goes from 17 s to 13 s (chapter 11).
    • The viewer has the pages ready before you reach them: while the view is still it draws the rest of the document, and scrolling is instant. The page moves by dragging with the right button (chapter 12).
    • Real annotations: marks edited with handles, straight, curved or elbow arrows, custom thickness, a circular pointer the size of the tip, partial eraser, text boxes, laser, foldable comments and exporting the PDF with the marks (section 12.3).
    • Clean folders: a .pltx holds only your document and its results, and Pyx's working folder does not pile up copies (section 4.2).
    • Tables and images: new wizards with a preview of the code, pasting from Excel into a grid and a style of your own that is remembered (sections 5.3 and 5.4).
    • Exact Ctrl+click between code and PDF, also below tables and figures produced by Python.
    • Finer proofing: red for spelling, blue for punctuation and spacing, green for style (section 5.9).
    • Figures no longer jump ahead of their section (section 11.3).
    • Updating with one button: Settings → General → Check for updates downloads, installs and reopens Pyx by itself (section 2.3).
    • Ctrl+R replaces the selected word in the whole document.

    1.4 How to read this manual#

    Chapters 2 to 4 explain how to install Pyx, what the window looks like and how to work with documents. Chapters 5 to 10 cover what you do every day: writing LaTeX, programming in cells, using your Jupyter notebooks, Python files and spreadsheets, and taking the results into the text. From chapter 11 on, compiling, the PDF viewer and the supporting tools are explained. At the end there is a table with every keyboard shortcut (chapter 15) and a troubleshooting chapter.

    Throughout the text you will find three kinds of box:

    Tip

    A faster or more comfortable way to do something.

    Note

    A detail worth knowing to understand what Pyx does.

    Caution

    Something that can give an unexpected result if you do not keep it in mind.

    Keys look like this: Ctrl+S. On macOS, Ctrl is Cmd. Buttons of the application look like this: Compile & view. The names of buttons and menus are those of the English interface; the screenshots show the Spanish one.

    2

    Installation and first start

    2.1 Requirements#

    • Windows 10 or 11 (64-bit), macOS 11 or later (Intel or Apple Silicon) or 64-bit Linux (Ubuntu 22.04 or equivalent).
    • 4 GB of memory and about 600 MB of disk if Pyx sets up its own Python, or 200 MB if it uses one you already have.
    • An Internet connection only the first time, if Pyx has to set up Python or LaTeX, and to look for updates.

    You do not need to install anything else. If you already have Python (Anaconda, python.org, Microsoft Store…) or a LaTeX distribution (MiKTeX, TeX Live, MacTeX), Pyx finds them and uses them. If not, it offers to set them up.

    2.2 Installing Pyx#

    Download the installer for your system from the releases page (github.com/LorGIOO/Pyx/releases). Next to each version's installers there is also this manual, as a PDF, of that same version.

    Windows:
    Pyx_2.2.0_x64-setup.exe. Open it and follow the wizard; it does not ask for administrator rights. When it finishes, .pltx files (and, if you want, .tex files) open with Pyx on a double click.
    macOS:
    Pyx_2.2.0_universal.dmg, for Macs with Intel and with Apple Silicon. Drag Pyx to Applications. The first time, open the application with right click → Open.
    Linux:
    .deb (Ubuntu, Debian), .rpm (Fedora) or .AppImage (any distribution: make it executable and open it).

    The installation folder also holds this manual in PDF (in Spanish and English), the example projects and the licence.

    2.3 Updating Pyx#

    Pyx updates itself, like VS Code. Settings → General → Updates shows the installed version and the Check for updates button. When you press it and there is a new version, Pyx downloads it, checks that it is identical to the published one (its SHA-256 fingerprint), installs it and opens again. It only asks if there are unsaved documents, because the installation closes the application for a moment. Also, a few seconds after starting, Pyx checks by itself and, if there is something new, the status bar offers Update to….

    The version you have is always in the title bar and in the window name (on the taskbar and in Alt+Tab). On macOS and Linux the button opens the version's page to download it.

    If the antivirus blocks the installer

    Pyx's installers carry no paid digital signature, and an antivirus may distrust a version that has just been published. Each version is checked with Kaspersky before it is published. If your antivirus still blocks it, allow the file in its exception list or try again a few minutes later.

    2.4 Setting up Python and LaTeX with one click#

    When it starts, Pyx checks whether there is a Python interpreter and a LaTeX engine. If either is missing, the Set up Pyx dialog appears (figure 2.1).

    Python.
    Pyx downloads uv, a very fast Python installer, and with it a standalone Python 3.12 with the libraries a calculation report uses: NumPy, SciPy, SymPy, pandas, Matplotlib, handcalcs, Pint, openpyxl, IPython and jedi. It takes one to five minutes depending on the connection, and uses about 400 MB.
    LaTeX (Tectonic).
    A single program of about 30 MB that, the first time it compiles a document, downloads only the LaTeX packages that document needs.

    Press Set up. You will see live what is downloaded and installed. When it finishes, Pyx uses that Python and that LaTeX.

    Where it is installed

    Everything stays inside Pyx's data folder: %LOCALAPPDATA%\com.pyx.studio on Windows, ~/Library/Application Support/Pyx on macOS and ~/.local/share/pyx on Linux. The PATH is not changed and no other installation is touched. The program folder (%LOCALAPPDATA%\Pyx) holds only the program: compiles, logs and Python environments always go to the data folder. When you uninstall Pyx, the uninstaller offers to delete it too.

    If you already have Python and LaTeX, the dialog does not appear. If you close it with Not now, you can open it later from Settings → Python cells → Pyx's Python or Settings → Compilation → Download Tectonic. Don't ask again keeps it from appearing at start.

    2.5 Choosing the Python interpreter#

    Pyx uses, in this order:

    1. the interpreter you chose (Python → Interpreter, or Settings → Python cells → Python path);
    2. the Python Pyx set up itself;
    3. a system Python that has NumPy;
    4. any other Python that works.

    The status bar always shows the interpreter in use. The Interpreter drop-down of the ribbon's Python tab lists every one Pyx finds on the computer (each says whether it has NumPy) and lets you pick a specific .exe, for instance an Anaconda environment's.

    2.6 The start screen#

    With no document open, Pyx shows the welcome screen (figure 2.2). From it you create a new document (Ctrl+N), open an existing one (Ctrl+O) or open a project folder. A .pltx or .tex file also opens with a double click on it in the file explorer.

    3

    A tour of the interface

    Figure 3.1 shows Pyx's window with a report open. Each number is an area explained below.

    1. Title bar. Pyx's version, the name of the active document (a dot in front means unsaved changes), the undo and redo buttons and the Settings gear.
    2. Ribbon. The tools, grouped in tabs: File, Home, Math, Python and View. They are described in section 3.1. As in Word, it adapts to the window width: with little room the groups get compact and, in the end, fold into a button that unfolds them.
    3. Document tabs. One document per tab; + creates a new one. Images and web pages produced by cells can also open as tabs.
    4. Side panel. A strip of icons that opens the Structure, table of contents (TOC), Symbols, Explorer and Search in project panels.
    5. Editor. The document's LaTeX code, with line numbers, folding and highlighting. Next to each \py{} its current value shows in grey.
    6. Python cell. A block of code with its toolbar and its output below.
    7. PDF viewer. The compiled document, next to the code. Its toolbar is in section 12.
    8. Status bar. The state of the Python kernel (green: ready; amber: running; red: error), the interpreter and LaTeX engine in use, the result of the last compile, the word count and the caret position. If the document imports libraries the Python in use does not have, a warnorange⚠ Missing: … notice appears here and installs them with one click.

    3.1 The ribbon#

    File
    New, Open, Open folder, Close folder, Save, Save as and Close.
    Home
    Clipboard (paste, cut, copy, find); Compilation (Compile & view, Stop, View PDF and Log, as in TeXstudio); Format (bold, italic, underline, strikethrough, subscript, superscript, upper and lower case); Paragraph (alignment, lists, environments); Insert (Table and Image wizards); Table (add and remove rows and columns, align); Structure (sections, labels and font sizes).
    Math
    Inline or display mode, subscripts, superscripts, roots, fractions, auto-sizing delimiters, equation environments, functions, styles, operators, accents and spaces.
    Python
    New cell; Current cell and All cells (which becomes Interrupt while something runs); minimise or expand every cell; restart the kernel, clear and hide outputs; the Macros; the Interpreter and the state of the kernel.
    View
    Split the editor, close panels, zen mode, preview, side panel, compile log and terminal.

    3.2 The side panel#

    Structure
    The current file and those it includes with \input, \include or \subfile; one click opens them.
    TOC
    The document's table of contents (parts, chapters, sections…), with the caret's section highlighted, and the list of pending tasks (% TODO, \todo). One click goes to the line.
    Symbols
    Greek letters, operators, relations, arrows and other math symbols. One click inserts them.
    Explorer
    The project's folders and files, like VS Code's explorer: open, create, rename and delete, with the active file highlighted and a dot on those with unsaved changes. With File → Open folder it always shows that folder (the project's «parent folder»), even with no document open, and Pyx remembers it after a restart; with no folder open it shows the active document's. Close folder goes back to that mode.
    Search in project
    Search and replace in every file (section 5.10.1).

    Ctrl+Alt+Z turns on zen mode: the ribbon, the side panel and the status bar disappear, and only the editor and the PDF remain. A coloured dot next to the tabs shows the compile (grey: not compiled; blue: LaTeX; yellow: Python; green: success; amber: with warnings; red: error); one click goes to the first error and Ctrl+Alt+L opens the log. Esc goes back to the normal view.

    3.3 Themes#

    Pyx has three themes: Light, Dark and Blue. They are chosen in Settings → General → Theme and apply at once, also to the viewer's auxiliary window. The viewer's night mode also darkens the paper of the PDF to work at night.

    4

    Documents and projects

    4.1 Creating a document#

    New (Ctrl+N) asks which kind of document you want (figure 4.1):

    Pyx document (.pltx).
    LaTeX with Python cells and \py{}. It is Pyx's own format.
    LaTeX document (.tex).
    Pure LaTeX, plain text, compatible with any editor.

    The new document starts empty.

    4.2 The .pltx format#

    A .pltx is a container (a ZIP file, like Word's .docx) that holds only two things:

    • the document's code, LaTeX with its cells;
    • the results of the cells: when the document is opened again the numbers, tables and figures show without running anything, even on a computer without Python.

    That is why a .pltx weighs what your text weighs: a few kilobytes. The PDF and LaTeX's auxiliary files are not saved inside or next to the document: they live in Pyx's working folder (section 4.5). To get a copy of the PDF (to send or print it) use the viewer's Save a copy of the PDF button.

    Note

    Inside a .pltx the cells are LaTeX comments (%#python and %#end), so the code is still valid LaTeX. If you add cells to a .tex, when you save Pyx suggests saving it as .pltx.

    4.3 Opening, saving and closing#

    • Open (Ctrl+O) opens .pltx, .tex, .sty, .cls, .bib and .txt. .py files, images and PDFs open from the Explorer panel: code in the editor, images in a tab and PDFs in the viewer. Spreadsheets open in their own program.
    • Save (Ctrl+S) saves the active document, compiles it and shows the PDF.
    • Save as changes the name or the folder. Pyx warns if the document has unsaved changes when you close its tab (Ctrl+W) or the application.
    • Included files you do not have open are read from disk at every compile: what you change in them with another program goes into the next PDF.

    4.4 Projects of several files#

    A long report is usually split into a main document and several chapters it includes with \input{chapter1} or \include{chapter1}. Pyx understands that structure:

    • compiling a chapter compiles the main document that includes it;
    • the cells of every file run in the order they appear in the whole document;
    • the references, citations and labels of any open file are offered by completion;
    • the Structure panel shows the included files, and Search in project goes through all of them.

    4.5 Where Pyx keeps what is not yours#

    To compile, LaTeX needs a copy of the document with the Python values already in place, and it produces auxiliary files (.aux, .log, the SyncTeX index, the PDF). Pyx keeps them in its working folder, inside its data folder (%LOCALAPPDATA%\com.pyx.studio), never in your project's folder nor in the program's. Your folder holds only what you put in it.

    Those files exist only while Pyx is open: they are deleted when Pyx closes, and if a session ended badly (a forced close, a power cut) they are deleted at the next start. That is why the first compile of each session may do one more pass.

    The settings are also saved, readable, in %APPDATA%\Pyx\config.json (on Linux, ~/.config/Pyx). If Pyx loses its data they come back from there, and Settings → General can open that folder, export it and import it to take it to another computer.

    5

    Writing LaTeX

    5.1 Completion#

    When you type a backslash, Pyx suggests the commands that start with what you have typed, with a short description of each (figure 5.1). ↑ ↓ choose and Enter or Tab accept. Commands with arguments are inserted with their slots in place: \frac{num}{den} leaves num selected; Tab jumps to den.

    Automatic packages.
    If you accept a command from a package the document does not load (for instance \qty, from siunitx), «(adds \usepackage)» appears and, on accepting it, Pyx adds \usepackage{siunitx} to the preamble.
    Your commands.
    The commands the document itself defines with \newcommand, \DeclareMathOperator or \def are offered too, with their number of arguments.
    Environments.
    After \begin{ the environments are listed (figure 5.3). When you choose one, Pyx also writes the \end and the usual content: a table brings its column specification; a figure, its \includegraphics, \caption and \label. The first option, «{ … }», is for typing the name of an environment of your own.
    References, citations and glossary.
    Inside \ref{, \eqref{, \cref{… the labels of every open document are offered; inside \cite{, the keys of the .bib files you load; inside \gls{, the glossary entries and acronyms.
    Python values.
    Typing \py{ opens the list of the variables there are (figure 5.2): those the document's cells define and those of the notebooks and .py files it links, with the file each comes from. It works at any point of the expression (\py{rows(heading_ completes too) and, after a dot, offers the value's attributes.

    Tip

    Completion is adjusted in Settings → Completion: whether it appears as you type or only with Ctrl+Space, whether it is case-sensitive and whether it shows icons.

    5.2 The formatting ribbon#

    The Home tab formats the selection (or leaves the caret inside, with no selection): bold (Ctrl+B), italic (Ctrl+I), underline, strikethrough, subscript, superscript and case. The Structure group inserts sections (with their level shown: Pt, Ch, S1, S2…), labels, references and font sizes. The Math tab does the same with formulas.

    5.3 Tables#

    5.3.1 The table wizard

    Table (Home tab) opens the wizard (figure 5.4). The table is filled in a grid, like a spreadsheet: type in the cells, or copy a block from Excel and paste it in any cell with Ctrl+V, and the grid grows by itself to fit it. Enter goes down to the next row (and creates it if needed).

    Columns.
    Each with its alignment: left, centre, right or paragraph (p{width}, for text that wraps over several lines). On pasting, number columns are right-aligned by themselves.
    Rules.
    Four styles: booktabs (the professional one, without vertical rules), \hline at the top, under the header and at the bottom, full grid or no rules.
    Header.
    The first row, with a rule below and, if you want, in bold.
    Text cells.
    Escapes %, &, _, $… Turn it off if you write LaTeX in the cells ($x2$).
    Placement, caption and label.
    The table environment with its \caption above or below and its \label; From caption suggests the label from the caption. «Tabular only» inserts the table without a float.
    Font size and «if it does not fit».
    Smaller type for wide tables, or shrinking the table to the text width only when it does not fit.

    Below you see exactly the code that will be inserted and, if needed, the package the preamble must load.

    5.3.2 Your table style

    If you always make tables the same way (for instance booktabs, centred, small type and caption below), leave the wizard like that and press Save as my style. From then on every new table starts with those options. Pyx style goes back to the factory ones. The style saves the format, never the content.

    5.3.3 Pasting a table from Excel straight into the document

    Copy some cells from Excel, LibreOffice Calc, Google Sheets, Word or a web page and paste them in the editor with Ctrl+V: Pyx recognises rows and columns and writes the tabular (figure 5.5). Numbers are right-aligned, merged cells become \multicolumn, bold becomes \textbf and special characters are escaped. It also works with a single column. If you wanted the text as it was, Ctrl+Z leaves it as copied.

    In Settings → Editor → Paste tables you choose the rule style (automatic: booktabs if the project loads it) and whether the table should come inside a table environment, with the caret waiting in the caption.

    Tip

    Pasting copies the values once. For data that must stay current, link the workbook with \hoja and place the cells with \celda (chapter 9).

    5.3.4 Editing a table

    With the caret inside a tabular, the ribbon's Table group adds or removes rows and columns (keeping the column specification), adds or removes \hline and changes the column's alignment.

    What does not travel when pasting

    On pasting, Pyx removes the invisible characters that Word, Teams, PDFs and many web pages bring along (zero-width spaces, soft hyphens, direction marks), which break a command or a word without being seen, and splits PDF ligatures (ﬁ becomes fi). Inside a Python cell, non-breaking spaces also become normal spaces.

    5.4 Images and figures#

    Image opens the figure wizard (figure 5.6):

    • Browse… chooses the image and writes its path relative to the main document's folder, which is where LaTeX looks for it from, going up with .. if it is in another folder of the project (../999. Resources/2. Images/plan.pdf). A thumbnail of each image is shown.
    • The width, as a percentage of the text or in centimetres, a maximum height (the image keeps its proportions) and the rotation.
    • + Add another image places several side by side, as subfigures with their own caption: (a), (b)…
    • Placement, caption above or below and label. Below, the code that will be inserted.

    As with tables, Save as my style makes new figures start with your format.

    Tip

    Paste an image (a screenshot, an image copied from another program) in the editor with Ctrl+V: Pyx saves it in the project's imagenes folder and writes the figure with the caret in the caption. The folder is changed in Settings → Editor → Paste images.

    5.5 Formulas: preview on hover#

    Leaving the mouse over a formula ($…$, \[ … \], equation, align…) shows it drawn, without compiling (figure 5.7). If the formula contains a \py{}, it shows with its current value.

    5.6 Moving around the document#

    Ctrl+click on a reference.
    On \ref{fig:beam}, goes to \label{fig:beam}, even in another open document.
    Alt+← and Alt+→.
    Go back to where you were before a jump (a distant click, a reference, a search result, a jump from the PDF) and forward again. It also works across documents.
    Bookmarks.
    Ctrl+F2 sets or removes a bookmark on the line; F2 and Shift+F2 jump to the next and the previous one.
    Folding.
    The arrows in the margin fold environments and sections.
    Table of contents.
    The TOC panel goes to any section with one click.

    5.7 Smart editing#

    • Renaming \begin{itemize} changes its \end{itemize} at the same time; Ctrl+Z undoes both at once.
    • Enter inside a list adds a new \item; after a \begin{…} it opens the environment.
    • Ctrl+T comments or uncomments the selected lines. With a word or phrase selected inside a line, it comments only that: what follows moves to the next line, and since the % swallows the line break, the PDF does not change except for what was commented.
    • Bold, italics and the other formats, with the caret inside a \py{}, apply to the whole command, as to a word.
    • Alt+↑ and Alt+↓ move the line (or the whole cell) up or down.
    • Parentheses, brackets and braces close by themselves and their partner is highlighted.
    • Ctrl+Alt+D splits the editor into two panes with the same document or different ones.

    5.8 Checks as you type#

    Pyx underlines structural errors before compiling, like the texlab language server: unclosed braces, \begin and \end that do not match, repeated labels, \ref to labels that do not exist and unclosed $. After compiling, the errors and warnings of the log are also marked on their line. F8 and Shift+F8 go through every problem. If you have ChkTeX installed, you can add its style warnings in Settings → Compilation.

    5.9 Spelling, punctuation and style#

    As in Word, each kind of warning has its colour, and leaving the mouse on it shows why:

    red!75!blackRed: spelling.
    Words the dictionary does not know, in Spanish or English (Settings → Proofing). The Spanish dictionary is LibreOffice's RAE one extended with engineering vocabulary (structures, hydraulics, maritime engineering, geotechnics, statistics) and the names of common programs, and it understands how Spanish words are built: verbs with attached pronouns, prefixes, adverbs in -mente and superlatives. Right-click a word to see suggestions or add it to your dictionary.
    pyxblueBlue: punctuation and spacing.
    Spaces too many (two in a row, before a comma, inside a parenthesis) or missing (after a comma or a full stop), repeated signs, lower case after a full stop, and the space between a number and its unit (25 kN, not 25kN); in Spanish also «a el», «de el» and the missing opening ¿ ¡.
    okgreen!80!blackGreen: style.
    Repeated words («the the beam») and, in Spanish, expressions worth avoiding, redundancies and frequent mistakes.

    The checks ignore commands, formulas, code and comments.

    LanguageTool For a complete grammar check, Pyx can use LanguageTool, LibreOffice's engine. In Settings → Proofing → LanguageTool server type:

    • http://localhost:8081 if you run your own server (java -jar languagetool-server.jar –port 8081); the text never leaves your computer;
    • https://api.languagetool.org for the public server, which receives the document's text.

    Its warnings appear as problems (F8), each with the suggested corrections, applied with one click.

    5.10 Find and replace#

    Ctrl+F opens search in the document (or in the PDF, if the focus is on the viewer), with case, whole word and regular expressions. Ctrl+R opens replace straight away: with a word selected, it looks for it in the whole document, marks every occurrence and leaves the caret in «Replace» to type the new word; Replace all changes them at once (and Ctrl+Z undoes it).

    5.10.1 Searching the whole project

    Ctrl+Shift+F opens the Search in project panel (figure 5.9). It searches every file of the project folder (.tex, .pltx, .bib, .py, .sty…) and groups the results by file; one click opens the file with the match selected. Open documents are searched as they are in the editor, with their unsaved changes.

    The ▸ arrow unfolds replace. All replaces in every file: in open ones the change happens in the editor (it can be undone); other text files are saved directly, after you confirm.

    6

    Python cells

    A cell is a block of Python inside the document. In the file it is written between two LaTeX comments:

    Pyx · LaTeX
    %#python
L = 6.0
q = 12.5
M = q * L**2 / 8
%#end

    In the editor you do not see those two lines: Pyx draws the cell as Jupyter or VS Code do, with its toolbar above and the output below. The cell does not appear in the PDF; what appears is what you decide to show (chapter 7).

    6.1 Creating and running cells#

    New cell:
    Ctrl+Alt+C or New cell. It is created empty, with the caret inside.
    Run the cell:
    Ctrl+Enter, or the ▶ button on its left.
    Run and advance:
    Shift+Enter runs the cell and takes the caret below it.
    Run all:
    Ctrl+Alt+Enter resets the namespace and runs every cell from the start.
    Interrupt:
    the ■ button that replaces ▶ while the cell runs, or Interrupt in the ribbon. The variables computed until then are kept. If the cell does not respond, a second click ends the process.

    The cell's toolbar (visible when the caret is in it) has, as in VS Code: run the cells above, run this one and the ones below, split the cell at the caret, more actions (cut, copy, insert above or below, clear the output, copy the output) and delete.

    Tip

    A click on the blue bar on the left of a cell folds or unfolds it; the same with its output's. Minimise all in the Python tab folds them all at once.

    6.2 Outputs#

    Below each cell appears what it produces, in the order it produces it:

    • the text of print() and the warnings;
    • the value of the last line, if it is an expression (a number, a list, a DataFrame…);
    • pandas tables, formatted (figure 6.1);
    • Matplotlib, Plotly, Bokeh or Altair plots (figure 6.2);
    • LaTeX formulas (SymPy, handcalcs), HTML, Markdown, images, audio and video.

    The number in brackets is the execution counter, as in Jupyter, and next to the result is the time the cell took. Images and HTML pages can open in a tab or in the browser.

    Note

    Outputs are saved inside the .pltx: when the document is opened again they show without running anything. If the cell changes, its result is marked «out of date», so that a number that no longer matches its formula never passes for a current one.

    6.3 Errors#

    If a cell fails, the output shows the error with its traceback, in colour and with the document's line numbers: a click on «line 12» goes to that line. The error also appears in the log's Problems panel.

    Installing a missing package If the error is ModuleNotFoundError (the cell imports a library that is not installed), the Install … button appears (figure 6.3). Pyx installs the package in the Python it uses, restarts the kernel and you only need to run the cell again. Also, when a document is opened, Pyx checks which libraries its cells import and, if any is missing, says so in the status bar.

    6.4 Python completion and help#

    Inside a cell, completion is solved by jedi (the same engine IPython and JupyterLab use) on the kernel's real variables: np.lin offers linspace and linalg (figure 6.4); df. offers the methods of the DataFrame you created; inside a string, as in pd.read_csv("da, it offers the files of the project folder.

    Typing the parenthesis of a call shows the function's signature, with the parameter you are typing in bold, and its documentation (figure 6.5). Leaving the mouse on a name shows its help. Esc closes it.

    6.5 The kernel#

    Cells run in a persistent Python interpreter, the kernel: variables and imports are kept between runs, as in Jupyter. Cells run from the main document's folder, so open("data.csv") reads the file next to the document.

    • Restart (Ctrl+Alt+R) starts with an empty namespace.
    • Clear outputs erases the outputs of every cell; Hide outputs hides them without erasing them (the calculations still go to the PDF).
    • If a cell modifies a library (for instance math.pi = 3), Pyx notices and, on recompiling from scratch, replaces the process with a new one so that the change does not contaminate the next calculation.

    Pyx supports handcalcs' magics (%%render, %%tex), display(), objects with _repr_html_, _repr_latex_ and similar, asyncio and cells with await.

    7

    From calculation to document

    Cells calculate; this chapter explains how to take their results to the PDF. There are four ways, from least to most elaborate: a value in the text, a conditional text, a complete table or figure, and the development of the calculation with handcalcs.

    7.1 A value in the text: \py{}#

    \py{expression} writes in the PDF the result of any Python expression, evaluated with the cells' variables:

    Pyx · LaTeX
    The beam spans \py{L} m and the maximum moment is
\py{round(M, 1)} kN·m.

    To format numbers use Python's f-strings: \py{f"{M:.2f}"} writes two decimals; \py{f"{N:,.0f}"}, thousands separators; \py{f"{x:.3e}"}, scientific notation.

    What it writes depends on what the expression returns:

    A number
    with all its significant digits, never in 1e+05 notation; a NaN or an infinity give an error instead of slipping into the PDF.
    A text
    as it is: it is your own LaTeX. That is why a function that returns the rows of a table ("1 & 2.5 \\...") goes inside a tabular.
    A pandas table
    (a DataFrame or a Series) is written as a complete tabular, like the one under a cell: \py{summary} inside a table environment. For more than 500 rows, show part of it (\py{df.head(20)}) or use tabletex.
    A Pint quantity, a SymPy expression
    or any object that knows how to draw itself in LaTeX is typeset as a formula.

    If a variable gets two values

    When two cells, or two linked files (chapter 8), give a value to the same variable, each \py{} shows the value the nearest cell or file above it gave, as when reading a notebook from top to bottom. A \py{} placed before all of them (a summary at the start of the report) shows the final value.

    In the editor, to the right of each \py{} its current value shows in grey, without compiling (Mathcad style). Those values update when cells run and on compiling; they can be hidden in Settings → Python cells.

    Note

    While you type, the grey values of expressions that would modify data (for instance list.pop() or next(iterator)) are not computed: they say «computed when compiling». So looking at the document never changes the results.

    7.2 One text or another: \pyif#

    \pyif{condition}{if true}{if not} chooses the text from a Python condition. The third argument is optional:

    Pyx · LaTeX
    The section \pyif{sigma <= f_yd}{\textbf{passes}}{\textbf{fails}}
with a utilisation of \py{f"{100*sigma/f_yd:.0f}"} \%.

    Both texts can hold any LaTeX, even other \py{} and \pyif.

    7.3 Complete tables and figures: the pyx module#

    Cells can import Pyx's helpers with from pyx import …; inside \py{}, tex, texesc, tabletex and figtex work directly, without importing them:

    figure(name)
    saves the current Matplotlib figure in the project's image folder (xref/) and returns its path, to use in \includegraphics{\py{path}}.
    figtex(name, caption=…, label=…, width=0.8)
    returns the complete figure environment: it is placed with a single \py{}. Call it in the cell that draws the plot and place the text it returns.
    tex(object)
    turns into LaTeX a SymPy expression, a Pint quantity with its units, a NumPy matrix or a pandas DataFrame.
    tabletex(df, caption=…, label=…, prec=…)
    returns a complete table from a DataFrame; prec is the number of decimals.
    texesc(text)
    escapes LaTeX's special characters in any text.

    7.4 A complete example#

    What follows was computed by a cell of this very manual when it was compiled. The cell is:

    Python
    P = 15.0          # load (kN)
L = 3.0           # span (m)
E = 210e3         # modulus of elasticity (MPa)
I = 8356e4        # second moment of area of an IPE 300 (mm4)

deflection = P * 1e3 * (L * 1e3)**3 / (3 * E * I)  # mm
allowable = L * 1e3 / 300                           # mm (L/300)
# ... the plot with Matplotlib ...
plot_path = figure("deflection")

    And the document's text is:

    Pyx · LaTeX
    The deflection at the tip is \py{f"{deflection:.2f}"} mm, \pyif{deflection <= allowable}
{less}{more} than the allowable \py{f"{allowable:.1f}"} mm.

    which in the PDF becomes:

    En el PDF

    The deflection at the tip is 7.69 mm, less than the allowable 10.0 mm. Figure 7.1 shows the deflected shape.

    If tomorrow the load changes to 20 kN, edit the cell and compile: the number, the comparison and the plot change at once.

    7.5 The development of the calculation: handcalcs#

    For the PDF to show the calculation step by step, as it would be done by hand, use the handcalcs library: import handcalcs.render in an earlier cell and start the cell with %%render:

    Python
    %%render
M_max = q * L**2 / 8
V_max = q * L / 2

    handcalcs writes each formula with its values substituted and its result, and Pyx places it in the PDF where the cell is. %%tex does the same and also prints the LaTeX code produced. These are the only cells that put content in the PDF by themselves; all the others appear only through \py{} and \pyif.

    Caution

    As in Jupyter, %%render only works after import handcalcs.render. If it is missing, the cell fails with a message that explains it.

    8

    Jupyter notebooks and Python files

    Many calculations already exist outside the document: in a Jupyter notebook you work on in VS Code, or in a .py file. Pyx uses them as they are, without copying code into the report:

    Pyx · LaTeX
    \pyfile{calcs/data.py}
\pynotebook{calcs/waves.ipynb}
The design wave height is $H_s = \py{Hs}$~m.

    \pynotebook{…} and \pyfile{…} are the same command and accept both kinds of file; without an extension, \pyfile{data} looks for data.py and \pynotebook{data} for data.ipynb. The path is looked for first in the main document's folder, as with \input, and then in that of the chapter holding the command. In the PDF the command writes nothing: from that point on, \py{}, \pyif and the document's cells use the file's variables as if they were their own, with the usual syntax. Ctrl+click on the path opens the file.

    8.1 What can be used#

    Everything the notebook or file leaves defined: numbers and texts, lists and dictionaries, pandas tables (which \py{} writes as LaTeX tables), NumPy arrays and functions. A function of the notebook can be called from the document, and it takes along everything it uses inside (other functions, dictionaries, modules such as np), even if the document does not name it:

    Pyx · LaTeX
    \begin{tabular}{ccccc}
  \hline
  $i$ & $H_{s,i}$ (m) & $p_i$ & $Z_i$ & $\ln(H_{s,i})$ \\
  \hline
  \py{rows_ln(heading, len(dict_lognormal[heading]))}
  \hline
\end{tabular}

    The notebook's images are not brought over: a figure is saved as a file in the notebook and placed with \includegraphics, as always.

    8.2 Without running them again#

    A notebook can take minutes to run. Pyx does not repeat it: it takes the values it already has, in this order.

    1. From Jupyter, live. If the notebook is open in VS Code, JupyterLab or Jupyter Notebook and you have already run it, Pyx copies from that kernel the variables the document uses, in tenths of a second. Nothing runs in the notebook and no trace is left: neither in its history nor among its variables. If you have run nothing in Jupyter since the last compile, they are not even copied again.
    2. From the saved values. With Jupyter closed, Pyx uses the last values it took, as long as the file's code does not change. They also serve a new \py{} that reads another small variable of the file.
    3. Running it once. Only if there is neither (the first time with Jupyter closed), Pyx runs the file, from its own folder, as Jupyter would. Its values are saved and the next compile no longer runs it.
    4. Only what changed. If you change the notebook's code with Jupyter closed, Pyx recovers everything its last run left (even from another day) and runs only the modified cells and those that depend on them. A notebook that took minutes the first time takes, after a small change, what that cell takes.

    Finding the open Jupyter kernel is instant even with many old kernel files: Pyx checks them all at once and remembers those that no longer answer. Recompile from scratch and Run all do not run the linked files again either. The compile log says, for each one, where its values came from and how long it took (figure 11.1), and the warnings point at the variables Jupyter does not have yet (those of a cell you have not run there).

    8.3 Watched while you work#

    With compile as you type on, Pyx checks the notebooks and .py files of the last PDF every second and a half: if you save them from VS Code, if the data they read changes (an Excel file, a CSV) or if you run cells in Jupyter, the PDF updates by itself, without touching anything in Pyx. A notebook function that opens a file with a relative path looks for it in the notebook's folder, whoever calls it.

    8.4 .py files and their cells#

    A .py file runs whole, or block by block if it uses the # %% separators of VS Code, Spyder and PyCharm (also # In[ ]:). With blocks, Pyx runs again only those that change, as with the document's cells; # %% [markdown] blocks are text and are ignored.

    8.5 Several files and variables with the same name#

    You can link as many files as you like, each in its place in the document. If two give a value to the same variable, each \py{} shows that of the nearest file above it:

    Pyx · LaTeX
    \pyfile{data.py}                  % Hs = 2.8
The design wave is \py{Hs} m.          % 2.8
\pynotebook{waves.ipynb}          % Hs = 2.89 (the lognormal mean)
The mean of the records is \py{Hs} m.  % 2.89

    The document's cells follow the same rule: a cell placed after \pynotebook{waves.ipynb} reads the notebook's Hs. The order in which files are used is the order in which they appear in the document, which can differ from the order in which you created them.

    9

    Excel and CSV data

    A project's data often lives in a spreadsheet: quantities, prices, test results. Pyx places them in the document straight from the file, without copying them by hand and without Python, with two commands:

    Pyx · LaTeX
    \hoja[Quantities]{data/works.xlsx}
The total budget is \celda{E8} euros.

    9.1 Linking the workbook: \hoja#

    \hoja[Sheet]{workbook.xlsx} (hoja is Spanish for sheet) links an Excel workbook (.xlsx or .xlsm) or a .csv file, and the sheet the cells that follow refer to. Without a sheet name the first one is used. The path is relative to the main document, as with \input. In the PDF the command writes nothing, and it can go in the preamble.

    It holds from that point until the next \hoja: one document can read several workbooks and several sheets. A chapter that has no \hoja of its own before its cells uses the main document's first one.

    9.2 Placing the cells: \celda#

    \celda (Spanish for cell) takes an address as Excel writes it:

    \celda{E4}
    the value of one cell.
    \celda{E4:E8}
    a range: a row comes out as a & b & c, a column as one table row per value and a range of several rows and columns as the body of a table. It goes inside a tabular.
    \celda[T]{E4:E8}
    the same range, transposed: the column comes out as a row, and the other way round.
    \celda{Summary!B2}
    a cell of another sheet of the same workbook.
    Pyx · LaTeX
    \begin{tabular}{llrrr}
  \toprule
  \celda{A1:E1} \\   % the header: row 1
  \midrule
  \celda{A2:E7}      % the body: six rows
  \bottomrule
\end{tabular}

    Numbers come out as Excel saved them, without extra decimals; the text of the cells is written as it is (an & or a % do not break the document). Like any text, a \celda can be formatted: \textbf{\celda{E8}}.

    9.3 Always current#

    Pyx reads the file at every compile if it changed. You can have the workbook open in Excel: change a number, save (Ctrl+S) and compile. What is read is what Excel saved, including the result of each formula; changes not yet saved are not seen.

    In a .csv, row 1 is the first line, as Excel shows it. The format of Excel in Spanish and other European languages is understood: semicolons between fields and the decimal comma.

    Note

    An address that does not exist, a sheet that is not in the workbook or a file that cannot be found do not stop the compile: the cell writes nothing and the log says why. The old .xls format is not read; save it as .xlsx.

    The example project 05-excel-data (in the examples folder of Pyx's installation and on the website) is a complete construction budget made this way.

    10

    Reactive execution

    Pyx knows which variables each cell defines and which it uses. With that it builds a dependency graph, the same idea marimo uses: if you change a cell, only that cell and those depending on it have to run again, not the whole document.

    10.1 What runs#

    Picture a report with five cells: the data, loading a large file, a simulation that takes half a minute, a plot and a summary table.

    • If you change the report's text, no cell runs.
    • If you change the plot, only the plot runs: the simulation is not repeated.
    • If you change the data, the cells that use that data run, directly or indirectly.

    Also, if a cell gives exactly the same result again (for instance, you type g = 9.81 again), those depending on it do not run: Pyx compares the values and cuts the chain (early cutoff).

    The log of each compile says how many cells ran and how many there were, for instance «Python cells: 220 ms (1 run of 5)».

    10.2 Out-of-date cells#

    When you edit a cell without running it, the cells that depend on it are marked in cascade with «out of date: depends on a modified cell» (figure 10.1). The edited cell says «result out of date». So you see at a glance which results no longer match the code.

    10.3 Shift+Enter, reactive#

    With reactive execution on (the usual), Shift+Enter runs the cell and then the cells that depend on what changed, and only those. If the cell needs a variable from another cell that has not run yet, that cell runs first.

    If you prefer Jupyter's behaviour (run only the cell you pressed), turn off Settings → Python cells → Reactive execution. The cells that depend on it are then marked out of date, and the next compile brings them up to date. A compile always runs only what is needed, whether this option is on or not.

    10.4 Guarantees#

    Running only part of the document must give the same numbers as running it all. Pyx guarantees it like this:

    • Modifying an object counts as defining it: if a cell does list.append(x), editing it re-creates the list first, so it does not grow twice.
    • Variables an edited or deleted cell stops defining are removed, and the cells that used them run again (and fail, as they would in a full run).
    • Random numbers are treated as shared state: if a cell uses np.random, the one that set the seed is repeated too.
    • If a cell reads a data file (an Excel file, a CSV) and the file changes, the cell runs again even if its code is the same.
    • What the analysis cannot follow safely (exec, global, IPython magics, from module import *) makes Pyx fall back to the classic rule: run from the first cell that changed or, if needed, everything.

    Note

    This part of Pyx is checked automatically with hundreds of randomly generated documents: for each, running only what the graph says gives the same result, variable by variable, as running the whole document.

    Tip

    Recompile from scratch (Ctrl+Alt+Shift+B) always starts with an empty namespace and runs every cell. It is the reference if you ever doubt a result.

    11

    Compiling

    Compiling turns the document into a PDF. Pyx does everything needed in a single action: it saves, runs the cells that need it, substitutes the \py{}, \pyif and \celda, runs LaTeX as many times as needed and shows the PDF.

    11.1 Ways to compile#

    Compile & view
    (Ctrl+Shift+B) compiles and opens the viewer if it was closed.
    Stop
    interrupts the compile in progress; the previous PDF is kept.
    View PDF
    shows the viewer without compiling.
    Log
    opens the compile log: errors, warnings and how long each part took.

    If you press Compile & view while it is already compiling, Pyx compiles once more, when it finishes, with the last thing you typed: the final PDF is always that of your last change. Two more options, outside the ribbon:

    • Recompile from scratch (Ctrl+Alt+Shift+B): a new kernel and none of the auxiliary files of earlier compiles.
    • Compile as you type, in Settings → Compilation: compiles by itself each time you stop typing for a moment (1.1 s by default; if the engine takes longer, it waits what it took last time, at most 10 s). Saving (Ctrl+S) also compiles and shows the PDF, unless you turn it off.

    While it compiles, the status bar shows the phase: «Preparing…», «Running Python…», «Typesetting LaTeX…» or «Loading PDF…». When it finishes it shows the result and the total time.

    11.2 Fast: the warm engine#

    After each compile, Pyx leaves a LaTeX process with the preamble (packages and fonts) already loaded, waiting. If the next compile has the same preamble, only the body of the document is typeset. In a template with many packages the saving is large: in a real report with 122 packages, the preamble alone cost 7 s of each compile. Compile & view, saving and compiling as you type use it; only Recompile from scratch starts from nothing. If you change the preamble, a .sty or the engine, Pyx compiles the normal way.

    Writing the PDF quickly XeLaTeX compresses the whole PDF to the maximum again at every compile, figures included. Pyx asks it for light compression: in the same report, each pass goes from 17.3 s to 13.5 s and the PDF grows only 3 %. If you are going to deliver the PDF and every megabyte counts, choose Settings → Compilation → PDF writing → Smallest possible file, or save a copy with Save a copy of the PDF.

    11.3 Figures and tables in their place#

    LaTeX places each figure and table where it fits best. A figure that does not fit in what is left of the page waits for the next one, and if it does not fit at the top of that one (because it is very tall) it can end up after the heading of the next section: the text «runs ahead» of the image. It is not a fault of Pyx: the same document, compiled in TeXstudio, gives exactly the same pages.

    With Settings → Compilation → Figures and tables stay in their section (on), all pending figures and tables are placed before each \section, \subsection and \subsubsection. The order of the PDF is that of the document.

    Tip

    For a particular figure that must go exactly here, use [H] (float package) instead of [htbp]: the figure wizard offers it under «Placement». And avoid negative \vspace around figures: they move the text, not the figure.

    11.4 Engines#

    Pyx works with xelatex (the default), pdflatex, lualatex and Tectonic. The default engine is chosen in Settings → Compilation → Default LaTeX engine; a document can ask for its own with a line % !TeX program = pdflatex at the start, or choose it on the same Settings page. With Tectonic no LaTeX distribution is needed: it downloads the packages each document needs the first time it compiles it.

    11.5 Bibliography, indexes and glossaries#

    Between the LaTeX passes, Pyx runs by itself the auxiliary tools the document needs, and only when what they read changes (the same rules as latexmk):

    • BibTeX or Biber (with biblatex) for citations;
    • makeindex for the alphabetical index (makeidx, imakeidx);
    • the lists of the glossaries package (glossary, acronyms, symbols), sorted as makeglossaries would, without needing Perl.

    It also repeats LaTeX when cross-references or the index change, until they settle.

    11.6 The log and the problems#

    The Log button (Home and View tabs) opens, under the editor, the compile panel with two tabs (figure 11.1):

    Problems
    the errors and warnings, from LaTeX and from the cells, grouped by file as in VS Code, each with its line; one click goes to the line.
    Output
    LaTeX's complete log and, at the end, Pyx's timings: how long the cells took (and how many ran) and how long the LaTeX engine took.

    Note

    Pyx compiles a copy of the document (.build.tex) with the values already substituted, in a working folder outside the project. The line numbers of errors are always translated to those of the original document.

    12

    The PDF viewer

    The PDF shows to the right of the editor and updates by itself after each compile, keeping the page and the zoom.

    12.1 The viewer's toolbar#

    Navigation
    first page, previous, page number (type one to go to it), next and last.
    Zoom
    zoom out, zoom in (or Ctrl+mouse wheel) and the current percentage, which goes back to 100 % with one click; fit to the page width or height.
    Tools
    select text or move the page with the hand. At any time, drag with the right button to move the page in any direction (also with the wheel pressed); with the right button pressed, the wheel zooms. If you prefer only one of the two buttons to drag, choose it in Settings → Keyboard shortcuts. A double click on the PDF turns on the loupe.
    Bookmarks
    the PDF's outline, to go to any section (section 12.5).
    Search
    (Ctrl+F with the focus on the viewer) searches the text of the PDF; Enter and Shift+Enter go through the results.
    Annotate
    opens the review bar: highlight, underline and strike out text, pen, marker, shapes, comments and the list of corrections (section 12.3).
    Night mode
    darkens the paper and lightens the text and black formulas; colours, plots and colour pictures are kept.
    Maximise
    hides the editor and leaves only the viewer.
    Auxiliary window
    takes the viewer out to a window of its own, ideal for a second monitor. Compiles keep updating it; when it is closed, the viewer goes back to its place.
    Save a copy of the PDF
    and open in the external application (the system's PDF reader).

    12.2 Fast with huge documents#

    The viewer draws first the pages in front of you, in the background: neither the editor nor scrolling stop even if a page has a plot with hundreds of thousands of points. And when the view has been still for a moment, it draws the rest of the document, the nearest pages first, and keeps them: when you scroll, the pages are already there (in a real report, an A3 plan page with fifty images went from 4.5 s to appear to 4 ms). It stops as soon as you move and never uses more memory than the computer can give.

    Tip

    A plot with tens of thousands of points in vector form weighs on any viewer and on every compile. If you do not need to zoom into each point, save it with rasterized=True in Matplotlib (axes and text stay vector) or as a PNG at 300 dpi.

    12.3 Reviewing and correcting the PDF#

    The Annotate button of the viewer's toolbar opens the review tools. Marks are saved with the document's PDF, follow the zoom and survive recompiles. While you hold a tool, the page does not move: neither by itself nor when drawing with a digital pen or a finger on a touch screen (which would normally scroll the page).

    Highlight, underline and strike out text.
    Select the text with the mouse: on release it is marked exactly over those words, line by line. The highlight blends with the page like a real marker.
    Pen and marker.
    Smoothed freehand stroke. The pointer is a circle, outline only, the exact size of the tip.
    Line and arrow.
    Straight, curved or elbow, with a head at the end, at the start, at both ends or none, and solid or dashed stroke. With Shift they snap to 0°, 45° and 90°.
    Rectangle and ellipse.
    With Shift, square and circle. The rectangle can have rounded corners.
    Text box.
    One click where it goes, and you type on the page, with its colour and font size.
    Comment.
    One click where it goes, and you type next to a coloured bubble. A click on the bubble folds it and leaves only the icon; another opens it. A button of the bar folds or opens all of them.
    Eraser.
    Erases the whole mark it touches or, if you choose, only the part it passes over. Its pointer is a circle the size of the eraser.
    Laser.
    To point at something for whoever is watching your screen: the stroke glows for a moment and disappears by itself. It is not saved.
    Select and edit.
    A click picks a mark: it moves by dragging it or with the arrow keys (Shift: ten at a time) and shows its handles, as in Figma: the corner and side ones change the size (Shift keeps the proportion), the ends of an arrow reorient it and the handle in the middle of a line curves it. With the mark picked, the bar changes its colour, thickness, shape and style. Del deletes it and a double click on a text or a comment edits it.

    Thickness and size are numbers of your choice (or with the wheel over the box). Ctrl+Z and Ctrl+Y undo and redo. The buttons at the end of the bar:

    • Copy the list of corrections: every mark, page by page, with the marked text and each comment, ready to paste into an e-mail.
    • Save the PDF with the annotations: a copy of the PDF with the marks drawn on its pages, which any reader shows and prints.
    • Delete those of this page and delete all (it asks for confirmation; Ctrl+Z brings them back).

    12.4 From code to PDF and from PDF to code (SyncTeX)#

    From PDF to code:
    Ctrl+click on a word of the PDF goes to the line of code that produces it, with that word selected.
    From code to PDF:
    Ctrl+Alt+F (or Ctrl+click in the editor) goes to the point of the PDF that matches the caret's line and highlights it for a moment.
    The PDF follows what you type:
    with automatic compiles, after each compile the viewer scrolls to what you are editing if it was out of view (it can be turned off in Settings → PDF viewer).

    It also works in projects of several files and with Tectonic: Pyx reads the SyncTeX index directly, without depending on external programs. It is exact also below a table or a figure written with \py{…} (which takes several lines in the PDF and one in the code), and on a page without text (a full-page figure, a plan brought in with \includepdf) it goes to the command that placed it.

    12.5 Bookmarks#

    The bookmarks button opens, to the left of the PDF, its outline (figure 12.1). If the document loads the hyperref package, the PDF's own outline is shown, with the page number of each entry and the section you are reading highlighted; branches fold with their arrow. If it does not load hyperref, the document's sections are shown, which Pyx takes to their place in the PDF through SyncTeX. One click goes to the section, also after recompiling.

    Python macros

    Macros automate repetitive editing tasks. In TeXstudio they are written in JavaScript; in Pyx, in Python. A macro is a few lines of Python that read:

    seleccion
    the text selected in the editor;
    texto
    the whole document;
    linea
    the number of the caret's line;
    variables
    the variables computed by the document's cells (read only);

    and leave in resultado the text that replaces the selection. If resultado stays None, the document does not change; what is printed with print() shows in a notice.

    Pyx comes with five example macros: convert to upper case, sort lines, turn lines into an itemize list, insert a table with the document's numeric variables and count the words of the selection.

    Run:
    the Macro drop-down of the Python tab, or Alt+Shift+1 to 9 for the first nine.
    Create and edit:
    Edit macros… in the same drop-down. Changes are saved at once; Examples brings back the factory ones.

    For instance, this macro turns the selection «3,5» into «\qty{3.5}{\metre}»:

    Python
    valor = seleccion.strip().replace(",", ".")
resultado = r"\qty{" + valor + r"}{\metre}"

    Macros run in a namespace of their own inside the kernel: they can use any installed library, but they do not modify the document's variables.

    Troubleshooting

    The status bar says «Python: —» or the kernel is red Pyx cannot find a Python interpreter that works. Open Settings → Python cells → Pyx's Python → Set up or update… for Pyx to set up its own, or choose a specific interpreter in the Interpreter drop-down of the Python tab.

    «LaTeX was not detected» Install MiKTeX (Windows), MacTeX (macOS) or TeX Live (Linux), or press Settings → Compilation → Download Tectonic. If you have just installed a distribution, restart Pyx so it finds it.

    A cell fails with ModuleNotFoundError The library is not installed in the Python Pyx uses. Press Install … in the cell's output, or the warnorange⚠ Missing notice of the status bar. If you use a system Python that does not allow installing packages (some Linux distributions), have Pyx set up its own.

    %%render does not work Add import handcalcs.render in an earlier cell. If the notice says IPython is missing, install it (or set up Pyx's Python, which already includes it).

    A \py{} comes out empty or with an error in the log The expression cannot be evaluated: a variable that does not exist (an earlier cell failed or has not run), a typo or an exception. The Problems panel gives the exact reason for each \py{}.

    A \celda{} comes out empty The log says why: the file was not found (the path is relative to the main document), the sheet is not in the workbook, or the address is not valid. Remember that what is read is what Excel saved: save the workbook before compiling.

    A linked notebook runs again Pyx only runs a notebook or a .py file when it cannot take its values: Jupyter does not have it open and there are no saved values of that same code. The log (Output) gives the reason in the «Linked» line. The most common one: the notebook's code has changed since last time (saving the notebook after editing a cell counts as a change). Then Pyx recovers what its last run left and runs again only the modified cells and those depending on them. To run nothing, open the notebook in Jupyter or VS Code and run it there: the next compile takes the values from that kernel.

    «Jupyter does not have …» in the warnings The document uses a variable of the notebook that its Jupyter kernel has not computed yet: run in Jupyter the cell that defines it and compile again.

    The result did not update after changing a data file Pyx runs a cell again if the file it read with open() (or with pandas, NumPy, openpyxl…) has changed. If you read it another way, use Recompile from scratch (Ctrl+Alt+Shift+B).

    A cell does not finish Press ■ in the cell or Interrupt in the ribbon. If it has not stopped after two seconds, the button becomes Force stop: it ends the Python process (the variables are lost) and the next run starts with a new kernel.

    The Windows installer does not open If when opening the installer Windows says it has no access to the file, it is the antivirus: it blocked it for being an unsigned program just published. Allow it in the antivirus or download it again a few minutes later. Your documents and Pyx's data folder are not touched.

    A figure comes out after the heading of the next section It is the normal behaviour of LaTeX with figures that do not fit (section 11.3). Check that Settings → Compilation → Figures and tables stay in their section is on, or use [H] in that figure.

    Compiling takes long

    • Check in the log (Output) whether the time goes to the cells or to LaTeX.
    • If it is the cells: with reactive execution only the affected ones are repeated; a slow cell that always runs probably reads a file that changes or uses something Pyx cannot analyse (exec, IPython magics…).
    • If it is LaTeX: check that the warm engine is on; very large figures (PNGs of several megabytes) also slow it down.

    The PDF does not match what I wrote The status bar says whether the last compile ended with errors. If in doubt, use Recompile from scratch, which reuses nothing from earlier compiles.

    Windows, menus or text look small or blurry Adjust the editor's font size in Settings → Editor → Typography, and the PDF's zoom with Ctrl+wheel.

    Glossary

    Cell
    A block of Python code inside the document, between %#python and %#end.
    Compile
    Turn the document into a PDF: run the cells that need it, substitute the values and run LaTeX.
    Dependency graph
    The relation between cells by the variables they define and use; it decides which cells must be repeated after a change.
    Early cutoff
    Not running again the cells that depend on another if that one gave the same result as before.
    jedi
    Python completion library used by IPython, JupyterLab and Pyx.
    Kernel
    The Python process that runs the cells and keeps their variables.
    Linked file
    A Jupyter notebook or a .py file the document uses with \pynotebook or \pyfile: its variables are available from that point without copying its code; or a workbook linked with \hoja.
    .pltx container
    Pyx's document format: code and cell results in a single file.
    SyncTeX
    Index that relates each point of the PDF to its line of code.
    Tectonic
    Standalone LaTeX engine that downloads packages when they are needed.
    uv
    A very fast Python and package installer, which Pyx uses to set up its own Python.
    Warm engine
    A LaTeX process with the preamble already loaded, waiting for the next compile.
