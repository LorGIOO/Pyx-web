¶ The back

Every report has a back.

Turn the sheet over: every number in the PDF is a line of Python that ran. Cells are LaTeX comments, so the file is still valid LaTeX.

§ 1Why

The report that lies without anyone noticing.

You calculate in a spreadsheet or in Jupyter. You copy the result into the document. A week later a datum changes: you recalculate, but that number in section 4 stays as it was. The PDF and the calculations no longer agree, and nobody knows until someone checks.

Try it yourself. Both columns start from the same calculation. Change the load, in the spreadsheet or in the line of Python, and see which of the two documents tells the truth.

§ 2How it works

Three gestures. The same ones its icon draws.

The caret that writes, the integral that calculates and the triangle that compiles.

  1. Write

    Your report in LaTeX, with completion of more than 300 commands, errors marked before compiling and a Spanish and English spell checker. Where a result will go, you type \py{…}.

  2. Calculate

    Python cells as in Jupyter, inside the document itself, with their output below. Next to each \py{} its value shows in grey, without compiling.

  3. Compile

    Pyx runs only the cells that changed, puts each value in its place and produces the PDF, shown alongside. You change a datum and start again: it does the rest.

§ 4Reactive execution

Only what a change reaches runs.

Pyx knows which variables each cell defines and which it uses, and with that it draws a dependency graph. A half-minute simulation is not repeated because you changed the colour of a plot.

  1. You edit the text
  2. You edit the plot
  3. You edit the data
  4. tests.xlsx changes
  5. You retype g = 9.81

If a cell gives exactly the same result again, those depending on it do not run: Pyx compares the values and cuts the chain (early cutoff).

§ 5Your notebooks

Your Jupyter notebook is already done. Don’t copy it.

One line links it: from that point on, the document uses its variables and functions as if they were its own. And since a notebook can take minutes, Pyx does its best not to run it again.

Right nowThe notebook is open in VS Code and you have already run it.

  1. From Jupyter, live. It copies from that kernel the variables the document uses, in tenths of a second. Nothing runs in the notebook and no trace is left.≈ 0.3 s
  2. From the saved values. With Jupyter closed, it uses the last values it took, as long as the code does not change.0 s
  3. Running it once. Only if there is neither. Its values are saved for next time.whatever it takes, once
  4. Only what changed. It recovers what the last run left and repeats only the modified cells and those depending on them.whatever that cell takes

Also with .py files (\pyfile{data.py}), whole or in # %% blocks. If you save them from VS Code, or the Excel file they read changes, the PDF updates by itself. And with \hoja{…} and \celda{E4} the cells of an Excel workbook go into the text without any Python.

And while you hold a tool, the page does not move: neither with a digital pen nor with a finger.
